## 后台第二轮：消掉重复的页面切换 —— 「配置示意图」并进右栏

**用户指出**：截图圈了两处 —— 左栏页面列表 + 「配置示意图」自带的页签，说「这两个切换重复了吧」。

**解法（不是再删一排，而是让预览并进右栏）**
`CockpitAdminView.tsx`：删掉独立的 `<section className="uk-admin-config-section uk-admin-config-preview">` 整节，

`.uk-admin-preview-tabs`（连同 `role="tablist"`）整条删除。**「选哪一页」全页只剩左栏一处**。

**踩到一个真坑（幸好量了没靠眼睛）**
`.uk-admin-live-screen` 是 `aspect-ratio:16/9 + min-height:480px`。并进右栏后容器只有 818 宽，
16:9 算出来 460 < min-height 480 → **`aspect-ratio` 在 `width:auto` 时是由高度反算宽度的**，
于是框被撑成 **853px 宽**，右栏横向溢出 50px（1218 视口下溢出 272px）。
修法：`.uk-admin-preview-block .uk-admin-live-screen{width:100%;min-height:340px;max-height:none}` ——
**把 width 锁死就断了「高度反推宽度」这条路**，再加一个 340 的保底防止窄屏被压扁。
**记账：`aspect-ratio` + `width:auto` + `min-height` 三者相遇时，min-height 会反向撑大宽度。**

**顺带修的窄屏折行**：右栏 < ~480px 时装不下预览（内部模块格最少要 340px 高），
把左选右改的折行断点从 `≤760px` 提到 **`≤1100px`**；折行后名称框的 1fr 轨道会拉很长，
所以在同一断点里给它 `minmax(0,200px)` 上限并 `justify-content:start`，别把 ↑↓ 甩到最右边。
≤900px 那条断点原写的「内部纵向堆叠 + min-height:620」还给预览留着（同权重、更靠后覆盖）。
同时删掉 `.uk-admin-config-preview .uk-admin-preview-tabs` 等 3 条已失效规则。

**结果**：编辑页内容区 1596.75 → **1360.8px**（较改版前累计省 554px）；
预览框宽 788（并进右栏后不再越界），16:9 精确；模块区距框底留 17px 余量，未被裁。

**验证**：1440 / 1680 / 1218 三档右栏横向溢出 0、页面横向溢出 0；1150 / 1100 / 1000 / 900 四档折行后同样 0；
点第 3 项 → 预览标题与右栏标题同时变为「出餐统计」；全页可切页面的控件只剩左栏 4 项（页签类节点 = 0）；

原来预览是「手搓迷你控件」（假进度条/假 KPI/假柱状图），跟真实页面差太远。**没有走「抽 JSX 复用」那条路**——

## 后台第四轮：左栏页面排序从「↑↓ 方按钮」改成「拖动把手」

**用户**：贴截图圈出左栏那组 ↑↓，问「箭头有没有别的设计方案」。

**先量再给方案**（1440 / 1280 两档实测，数字一致）：

| 项 | 实测 |
|---|---|
| 左栏 / 行 | 260px / **258×56** |
| 那组 ↑↓ | **56×26 = 行宽 21.7%**，两个 26×26 各自带 1px 边框，共 **8 个按钮**（4 行） |
| 名称框 | 120px（放 4 个汉字，46.5%） |
| 按钮里的字形 | U+2191/2193，在 26px 方框里只有约 8px 高，**框比字大 3 倍** |

结论：问题不是「箭头丑」，是**低频操作常驻了 8 个带边框控件**，且 `↑` 语义是「上移一格」——
把第 4 页挪到第 1 页要按 3 次。

**给四个方案让用户选**（show_widget 画了带 hover 的对照图，每张卡片鼠标移上去能看到悬停效果）：
A 拖动把手 / B 悬停才出现 / C 合成步进控件 / D 只给选中行。**用户选 A。**

**实现（`components/CockpitAdminView.tsx` + `.css`）**

1. 新增 `Chevron`（折角图标，替掉 `↑↓` 字符）与 `DragHandle`（SVG 画 6 个点，不用 `⠿` ——
   盲文字形在缺等宽字体时会掉成方框）。
2. 拖动状态：`dragId` / `dropGap`（state 供渲染）+ `dropGapRef`（**真值**）、`rowRefs`、
   `dragMoved`、`dragOriginY`、`pendingDrag`。
3. `beginDrag` / `moveDrag` / `finishDrag` + `movePageTo(id, targetIndex)`（拖动与键盘 ↑↓ 两个入口、
   同一套结果，都改 `draft.pages`，所以预览与发布不会出现「拖了但大屏没变」）。
4. JSX：`<DragHandle/>` 顶到行尾第三列；`OrderButtons` 保留但常态视觉隐藏。
5. CSS：`.uk-admin-drag-handle`（20px 热区 / 8px 视觉）、`.is-dragging`、`.is-drop-above/-below`、
   以及 `.uk-admin-order-actions` 的 `1px + clip-path:inset(50%)` 隐藏态与 `:focus-within` 显形态。

**四个必须记住的坑**

- **「点一下选中」vs「拖动」要 4px 阈值**：没有 `dragMoved`，只想选中一行也会被判成拖动。
  未过阈值前 `pendingDrag` 只记谁被按下，不进拖动态 —— 否则每点一下就闪一下高亮。
- **拖动结束浏览器还会补一个 click**，必须在行 `onClick` 里用 `dragMoved` 把它吃掉，
  否则「拖完顺手把别的一行也选中了」。实测：先选「出餐统计」再把第 1 行拖到末尾，选中仍停在「出餐统计」✅。
- **落点线用伪元素，不能用 `box-shadow`**：`.is-active` 已经占了 `inset 3px 0 0` 那条左竖线，两者互相覆盖。
  并且用 `top:0` 而不是 `-1px` —— 列表是 `overflow:hidden`，负偏移会被裁掉一半（2px 线只剩 1px）。
- **缝隙号转下标要减 1**：往自己后面拖时先拔掉自己会让后面整体前移一格。
  另外「缝隙 == 自己的上沿或下沿」这两种位置**不画落点线**（松手不会变），让反馈说真话。
- **拖动不可键盘操作，所以 ↑↓ 不删**：`1px + clip-path:inset(50%)` 让它常态不可见**但仍在 Tab 序列里**，
  `:focus-within` 时才展开并让把手 `visibility:hidden` 让位。**不能用 `display:none`/`visibility:hidden`** ——
  那会把节点从无障碍树里摘掉，键盘就真没路走了。

**验证（CDP，`Input.dispatchMouseEvent` 发真事件，不直接调 JS 函数）**

- 拖动：按住第 1 行把手拖到末行下半 → `['生产烹饪','营养健康','出餐统计','行为监控']` →
  `['营养健康','出餐统计','行为监控','生产烹饪']` ✅；拖动中 `is-dragging`=1、落点线在末行底部。
- 键盘：**真 Tab 键**走一遍 → 从第 1 行名称框起 Tab#4 落到「上移」，该行容器由 1×1 展开为 **50×24**、
  把手转 `hidden`；回车触发重排（`营养健康` 上移到第 1 位）✅。
- 折叠布局：1000px 下行为 `46px 200px 20px`，拖动仍可用、横向溢出 0。
- 预览同步：拖完预览 iframe 顶部导航与配置**完全同序**（`['营养健康','出餐统计','行为监控','生产烹饪']`）✅。
- 回归：五视图 `cockpit 5 / nutrition 3 / overview 3 / behavior 5 / dish 3`，`colOv=0`、`bodyOv=False`、

## 咨询：能不能「直接在示意图上改配置」，以及它和「表单改 + 同步」哪个量大

**结论（已在回答里给出，记一下口径以便后续复用）**：不是二选一 —— 两种方式的**工作量大头是同一块**：
页面每个可编辑元素要有**稳定 key + 显示文案取自配置**。差别只在「输入通道」。

现成基础（这个原型已经具备的，使得「反向通道」增量很小）：
- 预览是**同源 iframe**（同一 prototype 路径 + `?embed=1`）→ 父页可直接 `iframe.contentDocument` 操作，
  也可以在 iframe 内**直接注入编辑器**，从而**完全绕开坐标换算**（iframe 内部 scale 恒为 1）。
- **postMessage 双向管道已有一半**（父→子推 config，子→父发 ready 握手），加反向 `cockpit-preview-edit` 很轻。
- 面板标题已经是 `moduleLabels?.[key] ?? 默认标题`，**寻址能力已完成一半**，缺的只是把 key 暴露到 DOM
  （`data-cockpit-field`，1 行/元素）。

两个通道的真实代价差异：
- **表单**：约 5 行/字段，零坐标逻辑，1:1 打字体验，**看不见的项也能改**。已建成 → 增量成本 0。
- **图上直接改**：一次性基础设施（编辑模式接管指针 + 命中判定 + 就地浮出输入框 + 提交/取消 + hover 提示），
  之后加字段近乎免费；但 ① **预览 scale≈0.62，13px 字只有 8px 高，就地打字很别扭**，需额外做「就地放大」；
  ② **看不见的项（编号 / 轮播秒数 / 视频流地址）压根改不了**；③ 同源才成立，将来预览若跨域这条路直接断。

**给出的建议是第三条路（性价比最高）**：
1. 先做**「点大屏 → 左侧表单项高亮 + 滚入视野」**（不做编辑，约 20–30 行，不需要反向通道，也不需要坐标换算）。
   它既是「直接在大屏上操作」八成手感的来源，**也是后面做真编辑的前置基础设施**（寻址 + hover 提示都要它）。
2. 确认好用后再上**反向通道**，只给「位置本身就是信息」的少数项做（页面名在大屏顶部导航上改、模块名在面板标题上改），
   看不见的继续留表单。

**已提示的风险**：新增面板忘了挂 `data-cockpit-field` → 「看得见但改不了」且是静默失败，
需要开发期校验（embed 模式缺字段就 `console.warn`）；编辑模式要暂停页面自身的轮播/演示时钟，否则点不准。

## 「配置示意图」改成静态（不能再点、但内容一个像素不许变）

**用户**：「这个在示意图里要不能切换，示意图也不需要动态，静态就行。不要改现在当前示意图的内容，只需要改成静态的」。

1. `CockpitAdminView.css`：`.uk-admin-live-frame>iframe` 加 `pointer-events:none;user-select:none`。
   **一行摁死全部交互**，渲染结果一个像素不变 —— 不用逐个控件去 disable。
   iframe 本来就 `tabIndex=-1` 不进 Tab 顺序，键盘也进不去。
2. `index.tsx`：给 `PageTopNav` / `TopHeader` 加 `inertNav?: boolean`，`CockpitModuleShell` 处传 `inertNav={embed}`。
   embed 时按钮**不挂 onClick** + `tabIndex=-1` + `aria-disabled`。
   **刻意不用 `disabled`**：disabled 会带上浏览器的置灰样式，示意图立刻和真页面长得不一样。

- 保持 `pointer-events:none` → 标记 **0**（事件根本没进 iframe）
- 临时改 `pointer-events:auto` → 标记 **1**（说明坐标精确命中该按钮）
两次坐标完全相同 → 一次性证明「拦得住」+「瞄得准」。
（坐标换算：iframe 内 `getBoundingClientRect` 是不缩放的自有坐标系，
全局 = `iframeRect.left + innerX * (iframeRect.width/1920)`。）

**实测**：`pointer-events=none`；iframe 仍 1920×1080、`.uk-screen` scale 恰好 1、外框 1066×600（比例 1.777）；

## 「示意图还在动」——把配置示意图做成真正的静帧（customer-cockpit-requirements-2）

用户反馈「不是说示意图保持静态吗，怎么还是在动」。上一轮只做了 `pointer-events:none`（挡交互）
+ `inertNav`（挡语义），**没有人去管「会自己走的东西」**。先量后改，量出来的动因有三类：

| 类别 | 具体 | 为什么前面的手段都拦不住 |
| --- | --- | --- |
| CSS 动画 | 13 个在跑（uk-dash / uk-route-flow / uk-breathe / uk-route-token-fade / uk-cctv-scan / uk-pulse / uk-stream-dot / uk-ticker …） | `pointer-events:none` 只挡输入，不影响动画 |
| JS 时钟 | 产线时钟 80ms 一跳（动线相位/设备状态/烹饪计时/温度全由它派生）、出餐批次累积、右上角时钟 1s（明厨亮灶 REC 时间戳读同一个值） | 定时器照跑 |
| **SVG SMIL** | 托盘的 `<animateMotion>`（生产流程里那三个料箱沿路径走） | **`document.getAnimations()` 里没有它**，`animation:none` 也管不到 —— 只看动画列表会得出「已经静了」的假结论 |

改法（全部只在 `embed` 下生效）：

1. `style.css`：`.uk-embed *, ::before, ::after { animation:none !important; transition:none !important }`。
   用 `none` 不用 `paused`：这些动效多带入场成分（`uk-pagoda-fade`、`uk-route-token-fade` 0% 都是 `opacity:0`），
   一 `paused` 就把元素留在透明状态、图上凭空少东西；`none` 让元素回到基础样式。项目里
   `prefers-reduced-motion` 那两条（`uk-pagoda-tier` / `uk-spotlight-*`）用的就是同一个手法。
   唯一例外：`.uk-route-token` 基础样式是 `opacity:0`，必须显式给回 `1`（否则动线上少三只托盘）。
2. `index.tsx`：新增模块级 `STATIC_PREVIEW`（`embed=1` 读一次）+ `PREVIEW_FREEZE_MS = 49_000`。
   四处定时器加 `if (STATIC_PREVIEW) return undefined`：产线时钟、出餐累积、右上角时钟；
   另外把 `useAutoScroll` / 圆环自动轮播 / 营养轮播三处已有的 `prefers-reduced-motion` 卫语句一并加上它
   （页面轮播早就被 `embed` 挡住了）。
3. **静帧定格在「演示跑到第 49 秒」**，不是 t=0。49s 是按 14s 动线节拍算的：
   ccj1 相位 0.500（停在炒菜机里 = 烹饪中）、ccj2 0.166（托盘在入口 2 通道 = 称重加料完成）、
   kx1 0.834（已出锅 = 烹饪完成）—— 三台设备三种状态、托盘都在图上。**改这个数前先按 `(T-delay)%14s`
   把三个相位算一遍**，别落在状态窗口边缘（t=0 那一帧是全线「未开始」+ 出餐记录空列表，看着像没开工）。
   实现：`flowStartedAt = Date.now() - PREVIEW_FREEZE_MS`（首帧即定格帧，不会先闪一下 t=0）。
4. **出餐记录在 `useState` 初值里一次算出来**，不放 effect：静帧不该存在「先按空记录渲染一帧再补上」。
   算 3 条最近到达 + 累计出餐量；`arrivalMsOf` / `outItemOf` 提到模块级，实时累积与静帧回填共用一份口径。
5. **SMIL 用 `svg.pauseAnimations()` + `svg.setCurrentTime(49)`**，并挂 `MutationObserver` 补刀
   （切页/改配置时 React 会重建 SVG 节点，暂停标记跟着节点一起没了）。
   拨的值必须与 `flowStartedAt` 同一个 `PREVIEW_FREEZE_MS`，否则会出现「JS 说这台在烹饪、托盘却停在别处」。
6. 顺手把时钟格式收成模块级 `clockStamp(now)`（原来初值是 `''`，首帧会渲染一次 `--:--:--`）。
   ⚠️ 名字不能叫 `formatClock` —— 文件里已有一个 `formatClock(分钟数) => "HH:MM"`（出餐明细行用的），
   tsc 直接报 `Duplicate identifier`。日期与时间是**两个空格**，页面按 `clock.split('  ')[1]` / `slice(-8,-3)` 取值。

**验收（都实际跑过）**
- 五个视图 embed 下：在跑动画 `0→0`、3 秒内文本变化 `0` 处、时钟不跳、滚动位置不变；console 0/0。
- 真页面（不带 embed）照旧在动：cockpit 13 个动画、3 秒 3~4 处文本变化，托盘位置 808→900（SVG 时间轴 7→10）。
- **后台 ?page=admin 端到端**：iframe `body.uk-embed`，5 秒前后两张截图**逐像素完全相同**（`getbbox()` 为 None）。
  —— 这一步是必须的：只查 `getAnimations()` 会漏掉 SMIL，前面就漏了。
- 五视图布局回归不变：cockpit 5 / nutrition 3 / overview 3 / behavior 5 / dish 3，`colOv=0`、`bodyOv=False`、`err=0 warn=0`。

**留着待用户定**：① 页头「暂停页面 / 当前轮播状态：轮播中」在静帧里是静止文字，读起来略怪（要不要在 embed 下改文案或隐藏）；
② 出餐量在真页面里约 2 分钟就会顶到 `TOTAL_PLAN`（100%），静帧定格在 49s = 3732/4620（80.8%）—— 这是既有演示数据口径，未动。

## 后台「配置示意图」改成图上所见即所得（customer-cockpit-requirements-2）

用户的问法是「修改项直接做在图上所见即所得 还是用之前的另外一个方案」。我先给了"不建议做图上直接改、
建议表单 + 点图定位"的推荐并列了三条代价（contentEditable 与 React 抢 DOM、iframe 缩放假坐标换算、
拆 pointer-events 闸门），**用户回「不管改动有多大 直接改」→ 按图上直接改做**。
（教训：这类"要不要做"的问题，用户可能只是要知道代价，不是要你替他否决；给完权衡就照他定的方向做。）

### 结论：不要用 contentEditable，用 iframe 内部的**受控 input**

最初判断里最重的那条代价（contentEditable 会被 React 重渲染吃掉光标/覆盖输入）是**真的**，
但它可以被绕开：**iframe 本身就是我们自己的 React 应用**（同源、同一个页面），
所以不需要在外层叠一层编辑器，直接在 iframe 里把标题渲染成 `<input>` 就行 ——
字号/字重/字距全部 `font:inherit` 继承，**没有一处坐标换算**，也没有一帧的 DOM 抢写。

`EditableText`（index.tsx）：非编辑态 `return <>{value || fallback}</>`（和改动前逐字相同），
编辑态返回受控 input，值放**组件本地 state**，`useEffect` 里
`if (document.activeElement !== inputRef.current) setDraft(shown)` ——
即**聚焦时故意不跟外部值同步**。理由：commit 要跨 postMessage 到后台再推回来，
中途拿一帧前的旧值覆盖就等于把刚敲的字删掉。实测同一帧内连打 15 个字符不掉字。

### 两道防线（缺一不可）

- **外面**（CockpitAdminView.css）：`.uk-admin-live-frame.is-edit>iframe{pointer-events:auto}`
  —— 只松开 iframe 这个整体，让事件能进到文档里；同时 `tabIndex` 由 -1 给到 0（键盘才能 Tab 进去）。
- **里面**（style.css）：`body.uk-embed-edit *{pointer-events:none!important}`
  + `body.uk-embed-edit .uk-inline-edit{pointer-events:auto!important}`
  —— 把整页命中测试关掉、只放行标题输入框。
  只要外面不要里面 = 把整张示意图都解锁了（轮播开关/餐段筛选/批次切换全是真按钮，点一下图就变了，
  用户只会觉得"说好是示意图怎么点一下就变"）。**取舍是让"能点的东西"精确等于"能改的东西"。**
  带 `!important` 是因为 `.uk-embed` 那套已经在改同一批元素，不加就被压。
  实测编辑态下：`.uk-inline-edit` PE=auto，其它（`.uk-page-carousel-toggle` / `.uk-switch-item`/
  `h2`/任意 button）全部 PE=none。

### 契约（14 处可编辑点）

- 可编辑：4 个顶部导航项（→ `page.name`）+ 左上驾驶舱名（→ `draft.name`）+ 11 处模块标题（→ `modules[].label`）。
  营养健康页 8 个、出餐统计页 8 个、生产烹饪页 10 个、行为监控页 5 个（4 导航 + 驾驶舱名）。
- `PreviewEditTarget` = `{kind:'module',key} | {kind:'page',id} | {kind:'brand'}`，
  **说的是"改的是哪一处"，不是"改数组第几项"**。模块 key 四页全局唯一，所以不用带 pageId；
  写回时按 key 扫全表定位，也就不会出现"在 A 页改、写到 B 页去"。
- 下行 `{type:'cockpit-preview-config', config, editMode}`，上行
  `{type:'cockpit-preview-edit', target, value}` / `{type:'cockpit-preview-exit'}`。
- **上行必须校验 `event.source === frameRef.current?.contentWindow`**：页面上不只这一个 iframe
  （原型目录、标注工具），不认来源的话任何一个 iframe 发同格式消息都能改草稿。
- Esc 要**分层**：在 iframe 输入框里按的 Esc 不会冒泡到后台窗口，必须发 `cockpit-preview-exit` 上来；
  后台自己那个 Esc 监听还要判 `defaultPrevented || pagePickerOpen`，否则一下关两样东西。
- 打字走 `setDraft(current => ...)` 函数式更新：两次输入落在同一帧会读到同一个旧值，后一条挤掉前一条。

### 顺手收敛的一处口径：留空 = 用默认名

11 处标题原来是 `moduleLabels['x'] ?? '默认名'` —— `??` 只兜 null/undefined，**兜不住空串**，
所以后台把「模块名称」清空，大屏上会留一个空白标题。图上编辑让"清空"变成很自然的动作，
于是统一收敛为 `value || fallback`（含后台表单那条路）。实测：清空「模块 1 名称」→ 图上仍是「今日菜单」。

### 一处漏接（自己发现）

`MealPlanModule` / `NutritionHealthModule` 传给 `CockpitModuleShell` 的调用**要显式带
`editEnabled`/`onEdit`**（那两个页面是独立组件、不吃 `{...previewProps}` 的 shell 那部分）。
第一版漏了 → 营养健康页和出餐统计页只有模块标题能改、顶部导航和驾驶舱名改不了，
靠"逐页签数可编辑点（期望 4+1+N）"才逮到。**跨组件透传参数时，逐页数一遍个数比看代码可靠。**

### 另两处踩点

- **顶部导航项在编辑态要换成 `<span>`**：`<button>` 里不能塞 `<input>`（嵌套可交互内容、非法 HTML，
  空格和回车会被 button 抢走）。视觉上把 `.uk-switch button` 的三条规则并成
  `button, .uk-switch-item` 选择器列表（数值抄两份迟早漂），只给 span 补 `display:inline-flex;cursor:text`。
  实测进编辑态前后导航都是 381×50/51，**`field-sizing:content` 真的生效**（4 个导航项各 60px 内容宽，
  没有塌成默认 20ch）。
- **后台编辑器是内层滚动容器（`.uk-admin-main`）在滚，不是 window**（`window.scrollY` 恒为 0）。
  所以 `Page.captureScreenshot` 的 `clip` 坐标会被算偏、截到块外面的东西。
  **后台的截图一律整屏截 + 手算 `容器.scrollTop`，不要用 clip。**

## 续：图上编辑扩到「换图」（Logo / 宝塔图片）+ 一次「啥都没改」的教训

用户追加要求：「我要直接可以在示意图上修改标题文字和更换 logo图片、宝塔图片」。
同一个机制往上长一层即可——**文字换 `<input>`，图片换 `<input type="file">`**，
两条路的落点都是同一个草稿字段。

### 新增的契约

```ts
type PreviewEditTarget =
  | { kind:'module'; key:string }   // 面板标题 → moduleLabels[key]
  | { kind:'page';   id:string }    // 顶部导航页面名 → pages[].name
  | { kind:'brand' }                // 左上角驾驶舱名 → name
  | { kind:'logo' }                 // → logo
  | { kind:'pagoda' };              // → nutritionPagodaImage
```

`ReplaceableImage`：只读态**直接返回 children，不渲染包装层**——
这样"关掉编辑态时这棵子树与改动前逐字相同"是可证的事实，而不是靠 CSS 保证。

```tsx
if (!editEnabled) return <>{children}</>;          // ← 关键：只读态零成本
// 编辑态才有 .uk-img-edit 包装 + 角标按钮 + 隐藏 file input
onFile = f => { const r=new FileReader(); r.onload=()=> onEdit?.(target, r.result as string); r.readAsDataURL(f); }
```

### 两个思路要点

1. **文件选择框必须由 iframe 自己打开**（`inputRef.current.click()`），不能 postMessage 让父窗口代开：
   用户激活（user activation）是**按文档**计数的，跨文档代开可能静默失败。
2. 两层 `pointer-events` 门里，"能点的"要精确等于"能改的"：
   `body.uk-embed-edit *{pointer-events:none!important}` +
   只给 `.uk-inline-edit` / `.uk-img-edit-btn` 开 `auto!important`。
   实测编辑态下 `.uk-page-carousel-toggle`/`h2`/任意 `button` 都是 `none`，
   只有那两类是 `auto` —— 所以图上不可能"点着点着把页面切走了"。

### ⚠️ 教训：**看不见的入口 = 不存在的功能**

第一版「图上编辑」开关用的是 12px、白底、浅灰描边、淡蓝字——**长在白色后台页面上**。
用户滚过去没看见，回了一句「怎么感觉你啥都没改啊，没变化啊」。

- 这**不是代码问题**。当时的自证顺序（照抄，下次别再白跑一遍）：
  ① 量开关的 `getComputedStyle` → 旧值 `#fff`/`#d8dfe7`，确实毫无存在感；
  ② `curl` 直接抓 Vite 产出的模块，grep 新标识符确实在里面
     （`EditableText`×9、`VIEW_TO_ADMIN_PAGE`×6、`uk-inline-edit`、`uk-embed-edit`）；
  ③ 顺手排掉"端口串了"的可能：51721 是**另一个项目**（同路径 404），
     `dist/` 里那份是 17:59 的旧构建、grep「图上编辑」零命中。
  三条排除完才确定是"看得见"的问题，而不是"没生效"。
- 改法：浅蓝实底 `#e8f3fd` + 实线描边 `#2b6fa8` + 13px/600 + 铅笔/对勾 SVG 图标 +
  hover 态 + 打开后**反相**（深蓝底白字）。改后实测：
  关闭态 102×34 `rgb(232,243,253)`/`rgb(43,111,168)`；打开态 128×34 实底 `rgb(43,111,168)` + 白字。
- **写进项目约定**：给后台加任何入口，默认按"用户会漏看"来设计——有底、有边、有图标、有状态差。
  验收标准不是"代码里有"，而是"截图里一眼能找到"。

### 「恢复默认」怎么搬：一行两颗粒子

原来 `.uk-img-edit-btn` 自己 `position:absolute;right:-8px;bottom:-8px`。两颗按钮各自绝对定位会互相盖住，
所以加了个行容器 `.uk-img-edit-actions`（自己定位、`display:flex`），**恢复默认排在换图左边**：

- 容器右对齐 → **最后一颗（换图）的右沿永远贴角**，加不加恢复默认，主按钮位置逐像素不变

  相对圆左沿 +40.0、26×26，与基线完全相同）
- 恢复默认只在**已经换过图**（`canReset`）时出现 —— 没换过就没什么可恢复的

### 一个测量教训（差点误报成布局回归）

中途量到 `scale=0.4636`，一度以为预览框从 1306 缩到了 890、是我删表单引起的。

（另：`getBoundingClientRect` 给的坐标可能在视口外 —— 这次直接按 rect 裁图裁出一整块黑，
因为按钮在 y=1118 而视口只有 1060 高。裁图前先把目标滚进视口。）

### 2. ★ 「谁删了我的代码」怎么查：`.spec/acp/` 会话存档

项目里有 `src/prototypes/<原型>/.spec/acp/`：
- `threads/<hash>.json` —— 每个会话一个文件，键是 `version/threadId/updatedAt/run/repository`
- `repository.messages[0]` 是**用户那条指令原文**，`messages[1].content.parts[]` 是 agent 的每步
  （`tool-Search` / `tool-Read` / `tool-Editing files` / `tool-<命令行原文>`），
  每个 part 的 `output.formatted_output` 里存着当时的**文件内容或命令输出**（可能被截断）。
- `conversations.json` 是索引（`conversations/sessions/messages` 三个数组，`messages` 只存
  `{storage:'thread-file'}` 指针，真正内容在 thread 文件里）。

**这套东西能当"文件历史"用**：那些 `rg -n` / `sed -n` / `Read` 的输出带行号且格式统一

用一条正则 `CockpitAdminView\.tsx[:-](\d+)[:-](.*)` 把行号提出来、按行号去重，

### 4. 明厨亮灶视频流：新增「播放方式 + 轮播间隔」

需求：多画面时可切「网格平铺 / 轮播」，轮播要能设间隔；单画面时不能设。
- 数据：`streamLayout: 'grid' | 'carousel'`、`streamCarouselSeconds: number`（默认 `'grid'` / 10）
- 判定只算一处：`const singleStream = draft.kitchenStreams.length <= 1`（别在 JSX 各处重算）
- 单路 → **两个按钮 + 间隔框全部 disabled**，旁边写 `当前只有 1 路画面，无需设置`。
  刻意选"禁用 + 说明"而不是"隐藏"：这一行本身也是"这页能配什么"的信息，藏了会以为没这功能。
- 轮播间隔 **只在选轮播时出现**（不是"出现但灰着"）：它是轮播的从属参数，选平铺时根本无关，
  灰着只会让人猜"为什么点不动"。这和单路禁用是两回事：那是"暂时用不上"，这是"当前无关"。
- 禁用态刻意不做得几乎看不见：选中项禁用时保留蓝底但降饱和（`#a9bed3`），
  一眼能看出"当前是轮播，只是改不了"，而不是"啥都没选"。
- 分段按钮没有复用页签 `.uk-admin-config-tabs`（那个是"换一块内容看"，会让人以为点一下表单整块被换掉），
  也没做成来回切的开关（开关看不出另一个选项叫什么，而"平铺/轮播"这两个名字本身就是这行的信息）。
- 特异性坑：`.uk-admin-stream-interval .uk-admin-number input` 用**两级**选择器，
  因为 `style.css` 里那条共享的 `.uk-admin-number input` 跟单级写法特异性同为 0,1,1，
  胜负取决于两个 CSS 文件的加载顺序 —— 那是"改天换个 import 顺序就悄悄变样"的坑，不靠它。
- 实测：单路 `dis:true,true` + hint 在；点 ＋添加视频流 → 两个都 `dis:false`；
  切轮播 → 间隔出现且值 10；改成 15 → `保存草稿` → localStorage `{streamLayout:'carousel', sec:15, n:2}`
  → **重载后 UI 回来 `{rows:2, act:'轮播', dis:false, val:'15'}`**（完整往返，不只是内存里的值）。
- ⚠️ 如实说明：`kitchenStreams` 目前**只被后台表单自己消费**，大屏 `index.tsx` 里搜不到它 ——
  所以这套配置（含新增的播放方式）暂时是个"没有大屏消费者"的后台参数，和它原来的状态一致。

### 5. ★★ 数字统计条"被删了"：一个类名导致的**静默不可见**（最值得记的一条）

用户报「出餐统计和行为监控的数字统计被删了」。实际代码里两条 KPI 行的 JSX **一行没少**，
DOM 里节点齐全、有尺寸、有坐标、`elementFromPoint` 命中它自己（= 没被盖住），
typecheck 干净、console 无报错 —— **但屏幕上就是没有**。

根因在 `components/ExceptionReferenceView.css`（当天 19:41 新增的「异常状态参考」功能）：
```css
.uk-exception-summary-host > :not(.uk-module-exception-state) { visibility: hidden !important; }
```
这条本来是给「异常状态参考页」清空子元素用的，而 `uk-exception-summary-host` 被**无条件**挂在两处：
- `index.tsx` 的 `.uk-module-kpis.uk-plan-kpis`（排产/总览页的出餐数字统计条，5 项）
- `BehaviorView.tsx` 的 `.uk-mon-stats`（行为监控的异常数字统计条，6 项）

于是这两排数字**平时也**全部 `visibility:hidden`。修法是把 host 类并进条件：
`${exceptionState ? ' uk-exception-summary-host uk-has-exception-state' : ''}`。

**为什么这个 bug 能藏住（方法论，比修法更值钱）**：
1. **`getBoundingClientRect()` 量不出"画不出来"** —— `visibility:hidden` 的元素照样返回完整
   尺寸和坐标。我第一遍用 rect 探针 + 截图目测，结论是"块在、位置对"，完全查不出问题。
2. **`elementFromPoint` 也判不出来** —— 它只回答"这一点最上面是谁"，`visibility:hidden` 的元素
   **仍然参与命中测试**，所以返回它自己，看起来像"没被遮挡"。
3. **只有 computed `visibility`（或 `opacity`/`color` 与底色相同）能判**：
   正确判据是 `getComputedStyle(child).visibility === 'visible'`，逐子项数 `visKids/kids`。
4. 这类"改一个模块的异常态样式，顺手把另一个模块的内容藏了"的跨模块污染，
   靠 `uk-has-exception-state`（条件类）和 `uk-exception-summary-host`（当时无条件）**长得像**而存活：
   扫代码时两者一眼看去都是"异常态相关的类"，很容易以为都是条件的。
   **检查方法：这类前缀相同的 class 里，凡是不在 `${...}` 三元里的，全部列为可疑。**
5. 修完做了**机制自检**：手动给元素加上那两个类 → 子项立刻 `hidden` ✓ —— 证明异常态功能本身没被弄坏，
   只是被错挂到了常态上。
