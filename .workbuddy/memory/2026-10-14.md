## 烹饪区标题：改两行 + 数据驱动（用户在 A/B/C 里选了 B）

用户圈了「烹饪区 · 2 台炒菜机 / 1 台烤箱」，问"可能有多种且多个设备怎么展示"。
出了三方案对照（A 徽标条 / B 两行文字 / C 只显总数，带极端 4 类 8 台压力行），**用户选 B**。

### 最重要的发现：那行字是手写的，和节点是两份数据

`<text>烹饪区 · 2 台炒菜机 / 1 台烤箱</text>` 是写死的字符串，下面的节点却是从
`COCKPIT_MACHINES` 渲染的 —— 设备增减时节点自动变、标题不变，**这行字今天就已经会漂移**。
所以不管选哪个方案，第一步都是改成从设备数组统计。B 的实现：

- 主行（框外 y=64，位置没动）：`烹饪区 · {COCKPIT_MACHINES.length} 台`
- 摘要行（**区块盒内顶部 y=98**）：按 `id.split(' ')[0]`（'炒菜机 CCJ1' → '炒菜机'）分组计数，
  `炒菜机 ×2 / 烤箱 ×1`；每行最多 2 类，超出用 `tspan x + dy=14` 折行（4 类折成两行，
  实测 `['炒菜机 ×3 / 烤箱 ×2', '蒸箱 ×2 / 炸炉 ×1']`），仍在节点上方（节点 y=128 才开始）
- CSS：`.uk-zone > text.uk-zone-summary`（11px / #8fb6dc，和节点设备码同一档"标识类小字"）
- **节点 rect 一个属性没动**（动线 keyPoints 按设备中心手算，老规矩）

### 放置的取巧：摘要行放盒内而不是框外第二行

框外放第二行（y≈71）只够一行摘要的余量，4 类折行后第二行会压在区块边框上（rect top=80）；
放**盒内顶部**（80..128 之间本来就是空的）则 4 类折两行也放得下，且节点不用挪。

### 遗留

- **投料区「2 个入口」、出餐区还是手写的**，同样的漂移问题；入口通道是两个写死的 rect。
  要不要照同样模式改，等用户发话。
- 设备数据仍是「类型 + 码」塞在一个字符串里（`'炒菜机 CCJ1'`），类型靠 split 拆 ——
  demo 够用；接真实数据时应结构化成 `{ code, type, model }`，三处（标题统计/节点/台账）读同一份。
- 出方案对照时用了 show_widget 画深色 mockup（三个方案 × 常规/极端两档），用户直接在选项里挑了 B ——
  这种"先画出来再选"的流程比文字描述省一轮返工，以后设计选择题默认这么做。

## 配置示意图改成「死图 + 覆盖层」（文字色块 / 图片色块）

用户两次强调：示意图的底图是**死图**，改文字/图片不许动底图，
必须在原位置**盖一层色块**：文字位盖色块写新字，图片位盖色块贴新图。
色块要「明显区别背景、但别太显眼」→ 定成 #0a2f6b 底 + #1b7bd0 浅青边。

### 结构（index.tsx EditableText / DietPagoda + style.css 3611 起）

- ① 底图层：每个可改文字位**永远渲染 fallback（内置默认名）**，`visibility:hidden` 占位
  （不能用 display:none，会把定位基准也收走）；Logo 那颗「智」、宝塔那张 `dietPagoda3d`
  的 href 都写死，配置改不到。
- ② 文字层 `.uk-text-layer`（inline-block + position:relative）
  └ `.uk-text-layer-base`（隐藏占位）+ `.uk-text-layer-cover`（绝对定位、nowrap、inline-grid）。
  覆盖层**不参与布局** → 改多长的名字底图都不挪。编辑态内是受控 input + 隐藏量字器
  （`.uk-inline-edit-sizer`，量 draft||fallback 的宽度，让框贴着字，不依赖 field-sizing）。
- ③ 图片层：Logo = `.uk-logo` 里 `grid-area:1/1` 叠 `.uk-logo-cover`；
  宝塔 = SVG 里第二个 `<image class="uk-pagoda-photo-cover">`，
  `preserveAspectRatio="xMidYMid slice"` + clipPath + 兜底色块 rect（防比例不同露出底图）。

### ⚠️ 色块必须画在 ::before 上，不能写在覆盖层自己身上

给覆盖层加 background/border（哪怕 1px）都会让框内文字**垂直偏移 1~2px**
（实测，量墨迹）。画在 `::before{position:absolute;inset:-5px -7px;z-index:-1}` 上，
覆盖层盒子保持"与底图文字逐像素对齐"的那组取值，色块只是外扩的贴片 → 墨迹偏移 ≤1px。
`z-index:0` 必须留着：它让覆盖层成为 stacking context，否则 ::before 的 -1 会被面板背景盖住。

### 验证手法（/tmp/verify_layers2.py、verify_layers3.py）

- **墨迹比对**才量得出"字有没有对齐"：同一区域截三张（只有背景/只有底图字/只有覆盖层字），
  PIL 差分取 bbox。**rect 的 dy/dh 不算数**（inline 盒和 abs 盒本来就不同高，纯几何假象）。
- 量墨迹时必须把色块底色/边框/伪元素**全部临时关掉**，否则量到的是色块不是字。
- 底图零位移断言：fingerprint 的 key 用「标签+class+同类序号」，不能用 child 序号 ——
  往 SVG 里插一个 <g> 会让后面兄弟全错位一格，假报 25 个元素动了。
- 真实交互（Input.dispatchMouseEvent 点击 + insertText）验证过：点击能聚焦、打字能写回草稿。
  只用 `native setter + dispatchEvent(input)` 会绕过"能不能点到"这一段，别只做那个。

### 已验证结论

- 改长名前后：iframe 内 343 个元素 rect 位移 **0**；换 Logo/塔身前后：**0**（塔身层名、引线不动）。
- 真实点击+打字链路通；console 0 error；typecheck 干净。
- 已知代价（写在 CSS 注释里）：自定义名比默认名长时，覆盖层**向右溢出**
  （导航那侧会盖出胶囊外）—— 这是"底图不动"的必然结果，用户当前接受；
  若要"胶囊跟着变长"就等于放弃死图，得先确认再改。
- 交付图 `outputs/customer-cockpit-requirements-2-死图覆盖层编辑.png`。
