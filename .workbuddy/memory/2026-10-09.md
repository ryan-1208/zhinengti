## 膳食宝塔升级为立体 3D 版（用户嫌梯形平铺不够「高大上」）
用户选定方向：**立体 3D 宝塔 + 食物语义色**（问过 3 方向：3D 宝塔 / 科技描边发光 / 环形占比图；3 种配色：语义色 / 统一科技蓝 / 参考图暖色）。

实现：整个塔改为 **SVG 绘制**（`DietPagoda` 组件），替换掉原来的 CSS clip-path 梯形堆：
- **几何**：`PAGODA` 常量（cx/topHalf/botHalf/tierH），每层半宽线性插值 —— 层数增减几何自动重算，不再手写每层 width 百分比。
- **立体感来源**：每层 = 渐变面（左上亮→右下暗，`PAGODA_GRADIENTS` 每 tone 一组 [亮色,暗色]）+ 顶部高光带（白 0.3，比层身略宽 5px 模拟斜面受光）+ 底部暗边（黑 0.28）+ 白描边 0.35；塔底投影椭圆（radialGradient）+ 整体 CSS drop-shadow。
- **食物线稿图标**：`PAGODA_ICONS` 每 tone 一条 path（16×16 坐标系，transform 定位到层内左侧，随塔的斜边成阶梯排列），统一 `fill:none stroke` 线稿风 —— 深色屏上线稿比实心色块干净。
- **克数外置**：全部引到塔右侧标注列（viewBox x=442 起），细虚线（stroke-dasharray 3 3）从层中点引出 —— 解决顶层太窄放不下两行克数的问题，也让标注一列对齐（参考图的做法）。
- **氛围**：塔身后一道青色环境光椭圆（#25e0ee 0.13 → 透明，同驾驶舱主色）；入场动画 `uk-pagoda-rise` 自下而上逐层浮现（JSX 按 i×70ms 给 delay），`prefers-reduced-motion` 关闭。
- **尺寸**：`.uk-pagoda{flex:1;min-width:0;width:100%}` 吃满面板剩余高度，viewBox meet 自适应 —— 首版固定 max-width 660 时塔偏小、上下留白多，改成撑满后塔高 ~575px。
- **层名描边**：`paint-order:stroke` + 深色 stroke 当底衬，避免白字叠深色渐变发灰（比 text-shadow 干净）。

**量化验收**（脚本 /tmp/pagodachk.py）：6 层 faceW 194→449 递增、层名全部在层内（nameOutside false）、标注文字右缘 678 < SVG 右缘 744、图标/渐变各 6、console 0。五视图回归全过。

**教训**：CSS clip-path 梯形做「堆叠造型」到头了 —— 要立体感/图标/引导线这类精细视觉，直接上 SVG（JSX 里 map 生成 path + defs 渐变），几何用常量+插值算，别手写每层坐标。

## 修「百分数和进度条不在一行」：今日菜单·总完成率
用户截图：`78.8%` 单独一行浮在进度条上方。**最终形态是「压在填充条上」**（用户先否了浮在上方，又否了排在右边）。

根因：`.uk-menu-overall-track` 的 `<span>` 是 `position:absolute;right:2px;bottom:12px` —— 条本身只有 8px 高，`bottom:12px` 把百分比推到条**上方**。实测条 `top=303`、百分比 `bottom=299`，直接压在上一张摘要卡的底边（卡片底 291）上，看着就是「掉出去了」。

**① 先改成同行（被用户否掉）**：容器 flex 一行、条 `flex:1` 吃剩余宽度。问题：条被压短 46px，而且用户想要的是「放在条上」而不是「放旁边」。

**② 最终：数字压在填充条上**
```css
.uk-menu-overall-track{position:relative;margin:10px 2px 12px}
.uk-menu-overall-bar{height:16px;border-radius:8px;background:#0a2752}   /* 轨道样式从 -track 搬到 -bar */
.uk-menu-overall-bar + i / .uk-menu-overall-track i{display:block;height:100%;...}   /* 渐变填充不变 */
.uk-menu-overall-track span{position:absolute;right:10px;top:50%;transform:translateY(-50%);color:#eafff6;...}
.uk-menu-overall-track.is-in-fill span{color:#04263f;font-weight:700;text-shadow:0 1px 0 #ffffff59}  /* 落在亮渐变上换深色字 */
```
JSX 侧算 `right`：`right = calc(${100 - pct}% + 10px)`，让数字永远贴着填充条的右端内侧（跟着条尾走）。`pct >= 16` 才加 `.is-in-fill`；低于 16% 时退回轨道右端 + 浅色字 —— 已用 CDP 把填充条改成 8% 实测过退化分支（label 回到 x=382.3、颜色 `rgb(234,255,246)`）。

**两个必须记住的坑**：
- 填充条是 `width: X%`，百分比相对的是**轨道**宽度。所以必须多一层 `.uk-menu-overall-bar` 包裹 —— 直接把 `<span>` 塞进同一个 flex 容器，78.8% 会变成整行宽度的 78.8%（虚高/溢出）。
- 条高必须 ≥ 15px：11px 的字塞不进 8px 的条，硬压会上下溢出，看起来仍像「字浮在条外面」。轨道**不要**加 `overflow:hidden`（会裁掉填充条那层 9px 外发光）。

验证：label 落在填充条上（`labelOnFill:true`、右端距条尾 10px）、与条垂直中心偏差 0px、条高 16px 内完整包住文字、面板 overflow 0、五视图回归 console 全 0；周围元素没有位移（上一张卡底 291 → 行 top 301、下一块 top 329）。

**顺带发现（既有问题，未改，等用户决定）**：出餐统计页（page=dish）两个面板 `overflow-y:hidden` 且内容超高 —— 「统计口径」超 85px（最后一张卡被切一半）、「菜品任务明细」超 7px。
