# 智慧厨房驾驶舱 PRD

版本：V0.2｜日期：2026-10-09｜状态：当前原型导出稿

> 产品定位：面向后厨管理者、领导和参观讲解人员的智慧厨房生产展示驾驶舱。通过总览、出餐统计、行为监控和生产过程演示，帮助用户快速理解当前餐段的生产进度、菜品任务、设备协同和待关注信息。

> 数据边界：当前原型为静态结构演示，部分时间、温度、任务量和设备状态为演示数据，尚未代表真实设备或生产系统已接入。未接入或无法确认的数据不得展示为实时事实。

## 背景与问题

智慧厨房需要通过大屏向管理者和参观者展示无人智厨的生产组织方式，但真实生产系统、设备物联、工单状态时间戳和现场队列尚未全部接入。当前原型需要先把展示结构和统计口径讲清楚，同时避免演示数字被误解为真实生产数据。

当前需要解决的问题：

1. 用户能够从总览看到当前生产流程、餐段进度和关键设备。
2. 统计卡片的数字必须与页面明细使用同一口径；列表只有 3 道菜时，总数不能显示为 9 等与可见内容不一致的数字。
3. “烹饪中”的已烹饪时间、总烹饪时长和设备温度需要有明确展示规则；已烹饪时间要与右上角时钟同步，不能比真实时间快速推进。
4. 温度演示应稳定在目标温度附近，不能持续无上限升高。
5. 未接入真实数据时，页面要明确区分演示内容、待接入内容和真实业务事实。
6. 首屏需要在不增加虚假数据的前提下消化留白：总览保留按餐段分组的今日菜单，营养分析独立为“营养健康”页面，出餐记录与生产进度保持同高，现有内容按容器空间合理排布。
7. 流程演示卡片在刷新、重渲染和循环切换后都必须沿对应路线移动，不得停留在流程图左上角。

## 目标与成功标准

| 目标 | 成功标准 |
| --- | --- |
| 让用户看懂生产结构 | 总览能识别投料区、烹饪区、出餐区及设备协作关系；流程演示不会被误认为现场实时拓扑 |
| 让用户快速判断生产进度 | 当前餐段、已完成、未完成和投料区数字清晰可读，且与下方可见菜品列表保持一致 |
| 让烹饪过程可信 | 烹饪中任务显示已烹饪时间、总烹饪时长和设备温度；时间与右上角时钟同速，温度围绕目标值稳定变化 |
| 让统计口径可解释 | 顶部统计按当前餐段可见菜品任务计算，不混用托盘数、份数、工单数或跨餐段总数 |
| 让演示边界清楚 | 无真实数据源时显示演示或待接入状态，不使用“实时连接”“设备运行中”等无依据表述 |
| 满足展示屏使用 | 在确认的 16:9 横屏分辨率下，核心信息不裁切、不重叠、不依赖大屏触摸操作 |

## 用户、角色与场景

| 角色 | 场景与核心任务 |
| --- | --- |
| 后厨管理者 | 查看当前或下一餐段的生产进度，发现未完成菜品、投料待办和过程风险 |
| 客户领导、参观人员 | 了解智慧厨房的设备、流程和生产协同方式 |
| 接待／讲解人员 | 按总览、统计、行为监控等页面顺序进行讲解，不执行设备控制 |

典型场景：

1. 参观开始时进入“总览”，说明厨房生产区域、设备和出餐流程。
2. 用户查看当前餐段，结合生产进度和菜品明细判断任务是否完成。
3. 用户进入“出餐统计”，查看跨餐段的菜品任务汇总和明细。
4. 用户进入“行为监控”，查看行为事件演示或待接入提示。
5. 用户关注某道“烹饪中”菜品时，查看其已烹饪时间、总时长和设备温度。

### 本次包含

- 顶部品牌标题、页面导航和右上角当前时间。
- “总览”页面：
  - 当前餐段生产进度；
  - 生产节点和设备协同示意；
  - 投料区、烹饪区、出餐区结构；

  - 今日出餐数量、计划完成率、产出重量和趋势；
  - 生产趋势、出餐记录、厨房监控等演示模块。
- “出餐统计”页面：
  - 生产计划与完成情况；
  - 餐段筛选、日期或周期筛选的展示结构；
  - 菜品任务统计和任务明细；
  - 生产流程阶段和待分配／待投料信息。
- “行为监控”页面：行为分类、事件统计、抓拍或待接入内容的展示结构。
- “营养健康”页面：膳食结构建议、单品营养分析、今日菜单营养分析表和今日菜单餐品图片；营养数据、餐品图片与生产烹饪使用同一份菜品数据。
- 设备监控演示：2 台炒菜机、1 台烤箱和出餐出口的展示；设备状态只在有数据依据时表达为真实状态。
- 生产保障方向的风险指标、排产节点、称重加料准备度和关注工单结构，作为主规格约定的后续接入边界。
- 演示数据标识、待接入提示、无数据和字段缺失状态。

### 不在本次范围

- 真实设备启停、温度设定、配方修改、任务下发、设备重新分配或异常处置。
- 真实设备物联、工单状态时间戳、设备队列、库存、能耗、维保和食安数据接入。
- 由演示数据推断真实的库存缺料、设备故障、预计延误或实时产能。
- 原料品牌公示、供货渠道公示及其独立展示模块；后续如需要另行确认展示范围和数据来源。
- 把生产总数解释为托盘数、份数或跨餐段总量；当前页面按明确的可见菜品任务口径展示。
- iPad 控制端、多大屏集群管理和多控制端冲突处理；如需接入，另行确认控制协议和权限。
- 真实厨房三维建模或数字孪生状态同步。

## 用户故事

1. 作为后厨管理者，我希望看到当前餐段的总任务、完成任务、未完成任务和投料任务，从而快速判断生产是否按计划推进。
2. 作为后厨管理者，我希望统计卡片和明细列表使用同一批可见任务计算，从而避免数字与列表对不上。
3. 作为参观者，我希望看到投料、烹饪和出餐之间的关系，从而理解无人智厨的生产流程。
4. 作为参观者，我希望看到某道菜的烹饪时长和设备温度，从而理解设备如何执行烹饪任务。
5. 作为讲解人员，我希望页面明确标注演示数据，从而不会把原型示例误讲成现场实时数据。
6. 作为管理者，我希望在统计页查看菜品任务明细，从而定位未完成或待投料的具体菜品。
7. 作为管理者或参观者，我希望进入营养健康页查看单品营养和推荐餐品，从而快速理解今日菜单的营养结构。

## 数据模型

仅定义业务信息和展示口径，不预设数据库表或接口实现。

| 对象 | 主要字段 | 内容规则 |
| --- | --- | --- |
| 餐段 | 餐段名称、开始时间、结束时间、当前标识 | 当前餐段由系统时间和餐段时间窗确定；无匹配餐段时显示待确认状态 |
| 菜品任务 | 餐段、菜品名称、计划量、完成量、状态、设备、原料／调味信息 | 一条可见任务对应一行菜品；同一菜品多任务时需明确是否拆行 |
| 烹饪任务 | 菜品、开始时间、已烹饪时间、总烹饪时长、目标温度、当前温度、设备 | 已烹饪时间必须受真实时钟驱动；总时长来自任务配置；温度为真实遥测或明确标注的演示值 |
| 设备 | 名称、类型、型号、状态、当前任务、目标温度 | 当前演示设备为 2 台炒菜机和 1 台烤箱；未接入时不显示为真实运行状态 |
| 生产节点 | 节点名称、顺序、状态、关联任务 | 流程图和动画仅表达生产关系；无状态数据时使用流程演示标注 |
| 行为事件 | 事件类型、发生时间、区域、摄像头、图片、数据模式 | 真实事件、演示事件、无数据和加载失败要能区分 |
| 出餐记录 | 菜品、数量、时间、餐段、记录状态 | 记录与顶部统计须使用同一餐段和同一统计周期 |
| 今日出餐汇总 | 已出餐数量、计划数量、完成率、产出重量、趋势 | 数量和重量均来自同一出餐演示数据；趋势末点与当前数量一致 |
| 数据模式 | 真实、演示、待接入、缺失、失败 | 数据模式应在页面或模块内可见，不用缺失数据填充为 0 |

## 业务规则

1. 当前餐段由右上角系统时间对应的餐段时间窗确定；顶部汇总、菜品列表和烹饪任务必须使用同一个当前餐段。
2. 顶部四张生产汇总卡片按当前餐段可见菜品任务计算：
   - 生产总数 = 当前餐段可见菜品任务行数；
   - 已完成 = 当前餐段中完成量达到计划量的菜品任务行数；
   - 未完成 = 生产总数 − 已完成；
   - 投料区 = 当前餐段中处于待投料／投料中的菜品任务行数。
3. 顶部汇总不跨餐段累加，不混用托盘数、出餐盆数、原料重量或设备数量。若页面只展示 3 道菜，顶部总数必须按这 3 道菜对应的口径计算，不能出现 9 等无法由当前列表解释的数字。
4. 顶部汇总卡片标签不显示“（道）”等单位后缀，保持简洁；如果业务需要展示单位，应通过需求确认后统一修改，不在单个卡片中混用。
5. 菜品明细中的 `完成量 / 计划量` 与顶部统计必须来自同一条任务数据；明细可保留“盆”等业务计量信息，但不能反向改变顶部“任务行数”统计口径。
6. “烹饪中”任务显示三项过程信息：已烹饪时间、总烹饪时长、设备温度。总烹饪时长是任务目标时长，不随页面刷新随机变化。
7. 已烹饪时间 = 当前时间 − 烹饪开始时间；必须与右上角时钟使用同一时间基准，页面每秒最多推进一秒，不允许使用比真实时间更快的演示循环。
8. 当烹饪任务尚未开始、已暂停、已完成或缺少开始时间时，已烹饪时间显示对应状态或“—”，不能继续累计。
9. 设备温度有真实遥测时使用遥测值；没有真实遥测时只作为演示值展示，并保持在目标温度附近小幅波动，不得持续递增或超过合理范围。
10. 右上角时钟只表示页面当前时间，不等同于设备连接状态、生产系统更新时间或数据采集时间。数据更新时间需要单独标注，缺失时显示“—”。
11. 生产流程图中的“流程演示”动效只表示步骤关系，不代表对应设备正在真实运行；不得仅凭动效生成烹饪完成、设备故障或预计延误结论。
12. 没有可靠的现场状态时间戳、剩余耗时和设备队列时，不展示实时预计完成时间或确定的延误量；可展示静态计划与演示状态，但必须标注数据模式。
13. 过去餐段只展示已完成、及时或延迟结果；“未完成”主要用于当前或即将到来的餐段，避免把历史缺失数据误判为当前待办。
14. 风险工单按工单 ID 去重；同一工单满足多个风险条件时只计一单。等待超时不自动等同于出餐延误。
15. 不推断库存是否缺料。称重／加料统计只来自工单或任务状态，不从原料重量、菜品配方或任务未完成状态推断库存故障。
16. 数据缺失、接口未接入或加载失败时，优先显示“待接入”“暂无数据”“—”或错误状态，不使用 0 代替未知值。
17. 设备分配沿用既有算法结果；本页面展示分配结果和协同关系，不提供重新分配建议或设备控制。
18. 总览的今日菜单使用一份菜品列表，按早餐、午餐、晚餐等餐段分组；营养健康页的单品分析、今日菜单营养分析表和今日菜单餐品图片从生产烹饪的同一份菜品数据中选择，不另建一套菜品名称或营养值。
19. 今日菜单餐品统计图中的总产量、当前已完成、总产量重量、已完成重量和各餐品已完成／总重量必须使用同一份菜品任务数据；重量按称重投料量统计，已完成重量按各餐品完成盆数／计划盆数折算，汇总数字必须能由图中明细复核。
20. 今日出餐汇总中的已出餐数量、计划数量、完成率和产出重量必须使用同一统计口径；趋势图末点必须能解释当前数量。
21. 出餐记录与生产进度在同一首屏纵向区域内保持一致高度；列表只有现有记录时，通过行高和间距分配容器空间，不添加重复记录或占位数据。
22. 流程演示卡片必须绑定对应路线；在动画尚未开始、刷新、重渲染或循环切换时，卡片应保持隐藏或位于路线起点，不得显示在 SVG 原点或页面左上角。

## 权限与作用范围

- 当前原型为展示型页面，默认只读，不包含生产操作权限。
- 大屏用户可以查看页面内容和页面导航，但不能启停设备、修改配方、下发任务或处理工单。
- 如未来增加讲解端或 iPad 控制端，应另行定义控制端身份、目标大屏绑定、切换结果回执和未授权状态；本 PRD 不将其视为当前交付能力。

## 状态、异常与边界

| 场景 | 页面表现 |
| --- | --- |
| 正常展示 | 显示当前页面、右上角时钟和对应模块内容 |
| 演示数据 | 模块显示“演示数据”标识；演示时间、温度、任务量不被表述为真实现场数据 |
| 数据待接入 | 显示“数据暂未接入”或“待接入”，保留结构，不填充为 0 |
| 数据加载中 | 仅在对应模块展示加载提示，不阻塞其他页面导航 |
| 数据获取失败 | 有可用缓存时保留并标明更新时间；无缓存时显示获取失败和重试入口（如后续接入真实数据） |
| 当前餐段无任务 | 汇总显示 0 或空态，列表显示“当前餐段暂无任务”；不借用其他餐段数据填充 |
| 字段缺失 | 缺失字段显示“—”；不使用默认值制造实时事实 |
| 烹饪任务未开始 | 已烹饪时间显示“未开始”或“—”，温度显示“—”或待机状态 |
| 烹饪任务已完成 | 停止累计已烹饪时间，显示完成状态；不继续循环增加时间 |
| 烹饪时长异常 | 总时长缺失或非法时显示“—”，不根据动画速度猜测总时长 |
| 设备未接入 | 显示设备名称和演示／待接入状态，不显示“设备运行中” |
| 页面切换 | 保留导航当前项高亮，目标页面加载后再更新页面内容；不要求大屏触摸操作 |

## 字段、内容与交互要求

### 1. 全局头部

- 左侧显示“智慧厨房驾驶舱”。
- 顶部导航显示“总览”“营养健康”“出餐统计”“行为监控”。
- 右上角显示当前时间，作为页面时间基准。
- 需要表达数据不是实时接入时，在页面或模块显著位置显示“演示数据”。

### 2. 总览页

- 默认进入总览。
- 展示当前餐段和生产进度，内容包括生产总数、已完成、未完成、投料区。
- 汇总数字必须能由当前餐段下方可见的菜品任务列表复核。
- 展示生产流程节点、设备协同关系、今日菜谱与营养分析、今日出餐、出餐记录和厨房监控等演示模块。
- 今日菜单使用一份列表按餐段分组展示；营养分析统一进入“营养健康”页，原料品牌公示不在当前页面展示。
- 今日菜单模块同时展示总产量、当前已完成、对应重量和按餐品拆分的统计图；统计图按餐品展示已完成重量／总重量，与菜单明细同源。
- 出餐记录与生产进度保持一致高度；空间不足或有留白时只调整现有内容的排布，不补造数据。
- 流程图标注“流程演示”，不得使用动画替代真实生产状态。
- 流程卡片刷新或循环后仍沿既有路线移动，不得停在左上角。

### 3. 营养健康页

- 顶部导航可进入“营养健康”页，页面保持与总览一致的深蓝／青色大屏视觉。
- 左侧展示膳食结构建议，用于表达主食、蔬菜水果、动物性食物、奶豆坚果和油盐的结构关系；不将结构建议误写成实际摄入量。
- 右侧上方展示当前选中餐品的营养分析，至少包括能量、蛋白质、脂肪和碳水化合物，并标明“每100g估算”和“演示数据”。
- 页面下方展示“营养分析”表，按早餐、午餐、晚餐分组展示全部餐品的能量、蛋白质、脂肪和碳水化合物；该表替代总览页原有的营养分析列表。
- 右侧下方展示“今日菜单”，同步生产烹饪中的 10 道餐品，每道餐品配一张对应餐品图片；点击餐品后，营养分析区域同步切换。
- 营养健康页不展示原料品牌公示，不使用热销或销量类表述推断真实销售数据。

### 4. 菜品任务列表

- 每行至少显示菜品名称、所属餐段、完成量／计划量、当前状态和关联设备。
- 菜品处于“烹饪中”时，显示已烹饪时间、总烹饪时长和设备温度。
- 列表总行数与顶部生产总数采用同一过滤条件；筛选后，汇总数字应同步更新。
- 列表没有任务时显示空态，不保留上一餐段的任务数据。

### 5. 出餐统计页

- 展示计划、完成、未完成和投料等任务结构。
- 支持按餐段或页面已有筛选条件查看数据；筛选条件变化后，卡片、趋势和明细必须使用同一条件。
- 菜品任务统计使用明确的菜品／任务口径，不能把菜品种数、任务数和产出盆数放在同一数字中而不说明。
- 明细表用于解释汇总，不展示与汇总无关的隐含任务。

### 6. 生产保障模块

- 风险指标：排产节点落后工单、阶段等待超时、称重加料待办、预计延误量。
- 排产节点与现场状态并列展示；计划节点不是现场实绩。
- 称重加料准备度按工单状态汇总，不推断库存。
- 关注工单显示餐段／截止时间、菜品／工单、当前状态、计划偏差和出餐影响。
- 现场状态时间戳、可信预计完成时间和阶段阈值未接入或未确认时，显示“—”或演示标识。

### 6. 设备与行为监控

- 设备展示包含 2 台炒菜机、1 台烤箱、投料区入口和出餐出口的已确认演示结构。
- 设备详情、控制、故障告警和能耗不在当前交互范围内。
- 行为监控展示已确认的行为分类和事件结构；无真实监控数据时显示待接入或演示状态。

## 非功能要求

- 视觉：沿用当前深蓝／青色大屏视觉，横屏 16:9，确保远距离可读。
- 兼容：优先验证 1920×1080；其他分辨率需要验证缩放、裁切和文字可读性。
- 可靠性：所有动态演示内容不得因刷新造成明显跳变或数值倒退；烹饪时间必须以真实秒级节奏推进。
- 可解释性：所有统计卡片、列表和趋势需要能够追溯到同一筛选条件和同一数据模式。
- 数据安全：当前不接入真实个人、监控或设备敏感数据；后续接入需另行确认权限和留存要求。

### 产品验收

- [ ] 默认进入总览，顶部导航可切换总览、营养健康、出餐统计、行为监控。

- [ ] 顶部四张汇总卡片不显示“（道）”等单位后缀。
- [ ] 菜品任务明细可显示完成量／计划量；明细与汇总不产生互相矛盾的口径。
- [ ] 烹饪中任务显示已烹饪时间、总烹饪时长和设备温度。

- [ ] 温度保持在目标值附近稳定变化，不持续无上限升高。

- [ ] 餐品统计图同时展示总产量、当前已完成、总产量重量、已完成重量和各餐品已完成／总重量，数字与菜单明细一致。
- [ ] 营养健康页可从今日菜单中选择餐品，并同步更新能量、蛋白质、脂肪和碳水化合物分析。
- [ ] 营养健康页包含按餐段分组的今日菜单营养分析表；总览页不重复展示该营养分析列表。

- [ ] 今日出餐数量、完成率、产出重量和趋势使用同一口径，趋势末点与当前数量一致。
- [ ] 出餐记录与生产进度高度一致；现有记录填充空间时不增加重复或虚构记录。

- [ ] 汇总数字由当前列表数据计算或由同一数据源提供，禁止另写一套与列表无关的固定总数。
- [ ] 菜谱、营养分析、今日出餐和出餐记录的列表与汇总使用可追溯的同源数据。

## 风险与依赖

- 风险：当前任务、温度、设备状态和行为监控数据部分为演示数据，正式上线前若不替换数据源，可能被误解为现场事实。
- 风险：如果业务把“总数”理解为菜品行数、任务数、出餐盆数或托盘数中的另一种口径，当前汇总规则需要重新确认，不能只改数字。
- 依赖：真实工单状态、状态变更时间、烹饪开始时间、设备温度遥测和设备队列。
- 依赖：餐段、批次截止时间、阶段等待阈值和预计延误量计算规则需要业务确认。
- 依赖：正式部署分辨率、浏览器环境以及是否需要独立控制端需要技术方案确认。

## 开放问题

1. 正式业务中的“生产总数”是否始终按可见菜品任务行数统计，还是应改为工单数、计划盆数或其他口径？当前原型采用可见任务行数，作为避免 9／3 不一致的最小假设。
2. 菜品列表中的完成量／计划量是否继续保留“盆”作为明细单位？当前仅删除顶部汇总卡片的单位后缀，明细计量暂保留。
3. 真实系统能否提供每道菜的烹饪开始时间、目标时长和实时温度？若不能，烹饪中信息应统一标为演示或待接入。
4. 排产截止时间代表“烹饪完成”还是“实际出餐／取餐”？该答案会影响预计延误量和风险工单的业务定义。
5. 是否需要将主规格中的“生产保障”作为独立顶级导航页？当前原型的顶级导航仍为总览、出餐统计、行为监控，生产保障内容先作为接入边界记录。
