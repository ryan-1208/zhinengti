## 总体点评

原型对本 PRD 最难的约束——「不伪造实时数据」——处理得相当扎实：五类异常、候选清单与已部署清单的区分、容器/层架不默认联网、型号数量显示「—」、相对时间由时间戳计算、演示数据显式标注，这些都在实现里能逐条对上，而不是只在文档里写着。行为监控的数据状态覆盖也超出了常见水平，缺图、空数据、加载失败、未接入四态各有独立渲染，且失败态保留缓存并标明更新时间，符合 PRD「缺失不等于零」的要求。

本轮审查发现并**已修复**一个真实的 P0：iPad 控制页点击任一展示页按钮后，控制页自身会被同步逻辑导航走并消失。修复前用浏览器实测确认（点击「行为监控」后 hash 变为 `#page=behavior`、控制页被卸载），修复后四条联动路径全部正确。该问题连同另外两项（大屏挂载不采纳控制端状态、遗留页缺少演示标识）已在本轮闭环，不再计入下方问题清单。

当前最影响业务成立的是**运营驾驶舱页面无法在目标大屏完整呈现**：该页高约 1959px，1440×900 溢出 1059px、1920×1080 仍溢出 879px。它是按可滚动长看板构建的，而 PRD 的交付形态是固定 16:9 展示大屏（AC10 明确要求「无明显裁切」）。讲解时客户只能看到上方约 40%，后半部分内容在物理大屏上不可达。其次是规格对 PRD 非功能要求的承接缺口——PRD 第 226–233 行有六组适配与稳定性要求，规格中没有任何对应章节。

可以保留的有效表达：设备协同示意图用虚线区分「评审假设关系」而非伪造已确认关系；行为监控的统计口径与去重说明常驻页面而非藏在文档里；iPad 控制页在切换失败与未连接时都不虚报成功。这些是这个原型真正区别于「好看的假页面」的地方。

## P0-P3 优先级问题

### P1 - 运营驾驶舱无法在目标大屏完整呈现

- 证据：浏览器实测（`Emulation.setDeviceMetricsOverride` 精确视口）该页 `documentElement.scrollHeight` 为 1959px。1440×900 溢出 1059px；1920×1080 仍溢出 879px。页面主体 `.cc-body` 高度 1648px。对照 PRD:248 `AC10 在实际交付屏幕和 iPad 上检查文字、素材和操作，无明显裁切、重叠与变形`。
- 影响：PRD 定义的交付形态是固定横屏展示大屏（非触摸、非滚动），而该页是滚动长看板。在真机上讲解时客户只能看到上方约 40%，「设备运行状态」以下的内容在物理大屏上不可达，等于该页一半内容无法交付。这也直接使 AC10 无法通过。
- 修复方向：三选一，需业务方确认展示重点后再动——(a) 压缩为 16:9 单屏，合并或削减模块；(b) 拆为「运营总览」+「设备与运行」两页；(c) 明确接受滚动，并把讲解动线改为以 iPad 控制页驱动分页。若选 (a)/(b)，建议先与客户确认「客户领导真正要看的是哪 4–6 个指标」。

### P1 - 规格未承接 PRD 的非功能要求与关键业务规则

- 证据：PRD:226-233 含适配、可读性、稳定性、兼容性、网络、数据素材六组要求（如 `不得简单拉伸导致图片变形或文字过小`、`持续展示期间切页不白屏`）。规格全文检索「非功能」「稳定性」均为 0 命中。同时以下 PRD 业务规则在规格中无落点：PRD:195 `区分「设备具有称重能力」和「系统可读取称重数据」，两者不能互相推导`；PRD:189 `不显示虚构的任务百分比、当前批次或剩余时间`；PRD:208 `相对时间与绝对时间需一致，不能静态写死「2 分钟前」`；PRD:134 `未授权或目标大屏未连接时，禁用切页并说明原因。多控制端冲突处理不默认纳入首期`（规格检索「未授权」0 命中）。
- 影响：AC10/AC11 无对应验收口径；非功能要求无规格依据，交付屏幕适配与稳定性在验收阶段无据可查；「称重能力」与「称重数据可读」的区分缺失，后续实现存在把设备能力推导为数据能力的风险。
- 修复方向：在规格中新增「非功能要求」章节，逐条承接 PRD:226-233；把上述四条业务规则补入对应的页面模块说明与验收关注点。注意：这些规则部分已在实现中体现（如相对时间由时间戳计算），但规格未记录，属于文档滞后于实现。

### P2 - 演示数据存在重复事件编号

- 证据：`components/monitorDemo.ts` 中 `EV230922004` 出现两次（`grep -oE "EV[0-9]+" | sort | uniq -d` 唯一重复项）。
- 影响：事件编号是抓拍卡片的唯一标识，重复会让评审者或后续接入方误判为同一事件被渲染两次，削弱演示数据的可信度；若后续以此结构接真实数据，可能掩盖去重缺陷。
- 修复方向：把其中一条改为未占用的编号（如 `EV230922012`），并顺带核对全部编号的唯一性。

### P2 - 不可达代码与未使用函数

- 证据：`index.tsx:84` `function FrontCockpit(...)` 首行为 `return <SafetyCockpit />;`，其后的「明厨亮灶 / 客诉反馈」整段 JSX 永不可达（该组件本身在 `index.tsx:254` 被引用，问题在于分支不可达，而非组件无引用）。`index.tsx:182` `buildAlarmHtml` 定义后全仓无调用。
- 影响：规格与实现看起来支持「明厨亮灶」「客诉反馈」两个子页，实际无法渲染；评审者据此判断范围会得出错误结论。
- 修复方向：删除不可达分支与未使用函数；若这两个子页确需保留，则在 `FrontCockpit` 中接回子页切换。

### P3 - PRD 的去重口径矛盾未在规格中复述

- 证据：PRD:127-128 记录参考页数值 `19、102、0、2、37，合计 160，而总量显示 158`，并明确 `若同一事件可多标签，则需明确分类与总量不可直接相加`。规格采用「全部异常 = 五类之和」的单标签口径（`spec.html` 待确认事项中已声明 `不代表真实口径`），但未复述 160≠158 这一原始矛盾。
- 影响：演示结构已默认「可相加」，评审者可能误读为口径已定论；后续真实接入时才发现需要按多标签去重，返工成本更高。
- 修复方向：在规格边界页显式复述该矛盾，并声明演示值不构成口径结论，待监控侧确认去重规则。

## 完整性与项目对齐

- **核心用户**：PRD:35-46 定义两类角色——面向客户领导/参观者的讲解者，与操作 iPad 的讲解人。两者在原型中都有对应界面（展示大屏 + iPad 控制页），对齐成立。
- **主流程**：PRD:87-102 的流程与规格 mermaid `display-control-flow` 一致：启动大屏 → 读取当前页 → iPad 选择页面 → 成功则大屏变化并回写、失败则保持原页并提示重试 → 可返回首页。本轮修复后该流程在实现层真正成立。
- **入口出口**：入口为大屏 URL 与 iPad 控制页；出口为「返回首页」。默认页在本轮由「厨房总览」改为「运营驾驶舱」，与页面下线决策一致。
- **范围边界**：PRD:239 `食品安全、营养健康不作为本期页面保留`；规格已声明无食安、营养健康入口。原有「生产驾驶舱」页保留并可通过页面切换器进入，规格明确标注其不在 PRD 范围内。
- **资料冲突/待确认**：`src/resources/餐饮食堂大屏功能模块整理.xlsx` 列有食安台账、后厨直播、设备在线/离线/故障告警，与 PRD 的排除项和「未确认运行状态」方向相反。该表属食堂大屏竞品模块盘点，未被用作本原型需求来源，建议在规格参考资料中标注，避免后续误用。`src/resources/prd/客户驾驶舱需求PRD.md` 与库外 PRD 实质一致，无冲突。
- **回归边界**：PRD 要求只在「客户驾驶舱需求」副本内改造。规格与实现均遵守，原有 `dt-` 样式段未改动。

## 业务逻辑连贯性

- **流程顺序**：行为监控的「统计周期由 iPad 控制页切换、本页只读展示当前周期」在实现中成立；周期筛选控件只出现在 iPad 控制页的行为监控控制区，符合 PRD 对该功能的定位。
- **状态迁移**：大屏与控制端的展示状态经 `localStorage` + 自定义事件同步。本轮修复后语义清晰——控制页与保留旧页自身不参与跟随；首次进入时若 URL 未显式指定页面则采纳控制端当前页；URL 显式指定时以 URL 为准。实测四种路径均正确。
- **角色权限**：PRD:134 要求「未授权或目标大屏未连接时，禁用切页并说明原因」。未连接分支已实现（禁用切页 + 提示 + 重试）；「未授权」在规格与实现中均无对应，已列入 P1-2。
- **操作前置条件**：切换前置校验完整——未连接不切、切换中不重入、点击当前页不重复加载。切换失败保留原页并提供重试，不虚报成功。
- **数据生命周期**：断开连接时大屏保留最后成功内容（实现层未加显式守卫，但控制端在未连接时不产生写入，故实际不会出现脏切换）；获取失败态保留缓存并标明更新时间，符合 PRD 对缺失态的要求。
- **跨页面一致性**：页面 id 在 `DISPLAY_PAGES`、路由、`DisplayShell current`、`DisplayNav`、iPad 控制页与规格之间一致；本轮下线三个页面后，页面列表、底部导航、iPad 控制页按钮与规格同步更新，无残留入口。

## 状态、异常、边界与恢复

- **输入校验**：页面 id 与周期/数据状态 id 均经白名单校验后才写入与读取，未知值回落到默认，不会产生空白页或未定义状态。
- **边界条件**：行为监控四态（加载中、所选时段无事件、获取失败、监控未接入）均有独立且合理的渲染；加载中与未接入不填充零值、不显示骨架，避免「缺失被读成零」。
- **错误状态**：抓拍图同时覆盖「未返回图片」与「加载失败」两种情况，均保留事件类型、时间、区域与编号，页面不因此不可用。
- **并发/重复操作**：iPad 控制页对同一目标有切换中守卫，避免重复下发；重连按钮在重连中禁用。
- **集成失败**：控制连接中断有明确提示与重试入口，且不虚报切页成功。跨设备真实联动未验证——原型以同浏览器双窗口模拟，规格已声明该模拟不构成 AC02 的验收。
- **恢复路径**：切换失败 → 保持原页 → 重试；获取失败 → 保留缓存 + 标明更新时间；连接中断 → 重试重连。三条恢复路径均完整。
- **本轮已闭环**：控制页自我导航（P0）、大屏挂载不采纳控制端状态、切至保留旧页后控制端无法拉回首页、遗留页缺少演示标识。
